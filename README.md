# Классификатор изделий

Учебное веб-приложение на примере каталога электроники. В классификаторе хранятся группы, модели и изделия, их характеристики и единицы измерения. В разделе **Составы изделий** можно узнать, какие детали входят в комплект. В разделе **Маршруты изготовления** можно задать порядок сборки, материалы, инструменты и рабочее время, а затем рассчитать затраты на партию.

## Быстрый запуск

Откройте Docker Desktop и выполните команды из корня проекта.

**Если образ приложения уже собран**, запустите приложение и PostgreSQL одной командой.

```powershell
docker compose up -d --no-build
```

**Если запускаете проект впервые или изменили код**, соберите образ и запустите приложение.

```powershell
docker compose up -d --build
```

Gradle используется при сборке образа. Первый запуск сборки может занять несколько минут, пока Docker скачивает Gradle и зависимости проекта. Следующие сборки используют кэш Docker Desktop. Для запуска готового образа достаточно Docker Desktop, Gradle на компьютер устанавливать не нужно.

- [Главная страница](http://localhost:8080/)
- [Маршруты изготовления](http://localhost:8080/#/routes)
- [Составы изделий (BOM)](http://localhost:8080/#/bom)
- [Классификатор](http://localhost:8080/#/tree)
- [Swagger UI](http://localhost:8080/swagger-ui.html)

Если страница ещё не открывается, проверьте состояние контейнеров и журнал приложения.

```powershell
docker compose ps
docker compose logs --tail=80 app
```

Для остановки выполните `docker compose stop`. Данные PostgreSQL хранятся в томе `pgdata` и сохраняются между запусками.

## Практическая работа № 6. Приёмы моделирования маршрутной технологии

Задание 2-2 посвящено изготовлению изделий. Для изделия из классификатора можно создать один маршрут и заполнить его операциями. Номер шага задаёт порядок, например 10 — установить плату и комплектующие, 20 — установить комплект охлаждения, 30 — проверить запуск компьютера.

| Где работать | Что можно сделать |
| --- | --- |
| **Операции** | Добавить и изменить шаги. Для каждого шага указать расход материалов, инструменты или оборудование, профессию и время работы. |
| **Справочники** | Вести виды операций, инструменты, оборудование, почасовые ставки и закупочные цены. |
| **Расчёт партии** | Посмотреть порядок операций изделия и его компонентов, потребность в материалах, рабочее время и стоимость. Отфильтровать материалы по группе классификатора и время по профессии. |

Технолог задаёт порядок изготовления и нормы. Планировщик использует маршрут для расчёта партии. В приложении эти сценарии доступны через общий интерфейс.

### Создание маршрута

1. В классификаторе добавьте изделие и укажите его единицу измерения. В разделе **Маршруты изготовления** нажмите **Новый маршрут**, выберите изделие и введите код маршрута.
2. На вкладке **Операции** добавьте шаги. Для каждого укажите номер, название и вид операции. Виды операций можно добавить во вкладке **Справочники**.
3. Откройте шаг и добавьте расход, оснащение и нормы труда. Например, норма «4 винта на 1 изделие» даёт 12 винтов на партию из 3 изделий. В норме труда отдельно задаются минуты на подготовку партии и минуты на одно изделие.
4. Для покупной детали оставьте поле **Шаг изготовления компонента** пустым. Для компонента, который собирается отдельно, выберите шаг его маршрута, на котором он готов. При расчёте система учтёт операции его изготовления до этого шага включительно.

### Пример расчёта для защиты

Docker Compose включает демонстрационные данные. Откройте [маршруты изготовления](http://localhost:8080/#/routes) и выберите **Gaming PC Standard** с кодом `MT-PC-STD`.

1. На вкладке **Операции** раскройте шаг 20 «Установить комплект охлаждения». В строке расхода указан шаг 10 отдельного маршрута **Комплект охлаждения**.
2. На вкладке **Расчёт партии** введите `3` в поле **Количество изделий** и нажмите **Рассчитать**. Оставьте фильтры на значениях **Все группы** и **Все профессии**.
3. Для исходных демоданных результат содержит **6 вентиляторов**, **3 контроллера вентиляторов** и **4 операции**, включая сборку охлаждения. Время сборщика — **66 мин**, контролёра — **20 мин**. Материалы стоят **174 150 ₽**, работы — **900 ₽**, вся партия — **175 050 ₽**.

Количество изделий в партии вводится целым числом. Расход материала может быть дробным, например 0,5 м кабеля на изделие. В закупку входят покупные детали из основного и вложенных маршрутов. Если для какой-либо детали цена ещё не задана, приложение показывает стоимость материалов по известным ценам и перечисляет недостающие цены. Фильтры меняют отображаемые строки материалов и труда, итог относится ко всей партии.

## Классификатор и составы изделий

В **Классификаторе** можно вести дерево групп, моделей и изделий, назначать числовые параметры и перечисления, искать изделия и отбирать их по характеристикам. Настройки характеристик могут наследоваться от родительских групп. [Модель и правила классификатора](docs/catalog/README.md).

В разделе **Составы изделий** создаются спецификации (BOM). В черновик можно добавить компоненты из классификатора и задать их количество. Карточка показывает цены позиций при наличии данных. После утверждения состава новая редакция создаётся для того же изделия, а модификация — для другого изделия на основе утверждённой версии. Состав можно раскрыть до конечных компонентов и рассчитать потребность на выбранное количество комплектов. [Модель, API и примеры для задания 2-1](docs/bom/README.md).

## Архитектура и хранение данных

Проект использует **Java 17, Kotlin, Spring Boot, PostgreSQL 15 и Gradle**. Веб-интерфейс на JavaScript и CSS отдаётся самим Spring Boot. Сервер классификатора использует Spring Data JPA, а модули составов и маршрутов выполняют SQL-запросы через JDBC.

Для маршрутов запрос проходит от [веб-интерфейса](src/main/resources/static/js/views/manufacturing.js) к [RouteController](src/main/kotlin/com/classifier/controller/RouteController.kt). [RouteService](src/main/kotlin/com/classifier/service/RouteService.kt) проверяет входные данные и готовит результат, а [RouteRepository](src/main/kotlin/com/classifier/repository/RouteRepository.kt) выполняет запросы к PostgreSQL.

| Таблицы | Что хранят |
| --- | --- |
| `classifier_node`, `unit_of_measure` | Изделия, материалы, группы и единицы измерения. |
| `route`, `route_operation`, `operation_type` | Маршрут изделия, его шаги и справочник видов операций. |
| `operation_input` | Что расходуется на шаге и на какое количество изделий задана норма. Поле `operation_id` указывает шаг, который использует ресурс, а необязательное `source_operation_id` — шаг, на котором изготовлен компонент. |
| `asset`, `operation_asset` | Справочник инструментов и оборудования и количество оснащения для конкретного шага. |
| `labor_rate`, `operation_labor` | Почасовые ставки по профессиям и нормы времени для операций. |
| `numeric_parameter`, `node_numeric_value` | Определение параметра `PURCHASE_PRICE` и закупочная цена за единицу конкретного ресурса. |

[SQL-схема маршрутов](src/main/resources/route.sql) включает функции `route_expand` для просмотра операций на всех уровнях, `route_material_needs` для расчёта материалов и `route_labor_needs` для расчёта рабочего времени. [Демонстрационные маршруты и цены](src/main/resources/route-demo.sql) загружаются при включённых демоданных.

Эти запросы можно выполнить в Swagger UI. [Открыть Swagger UI](http://localhost:8080/swagger-ui.html).

| Запрос | Результат |
| --- | --- |
| `GET /api/v1/routes` | Маршруты, каталог и справочники. |
| `GET /api/v1/routes/{id}` | Шаги, расход, оснащение и нормы труда маршрута. |
| `GET /api/v1/routes/{id}/calculation?quantity=3` | Операции, материалы, труд и стоимость для трёх изделий. |

Идентификатор маршрута `id` берётся из ответа первого запроса. Для расчёта можно передать `group` — идентификатор группы материалов — и `profession` — идентификатор записи тарифа труда.

## Подключение к базе из IntelliJ IDEA

Поднимите PostgreSQL командой `docker compose up -d postgres`. В IntelliJ IDEA создайте источник данных PostgreSQL со следующими настройками.

| Поле | Значение |
| --- | --- |
| Host | `localhost` |
| Port | `5434` |
| Database | `classifier` |
| User | `classifier` |
| Password | `classifier` |
| JDBC URL | `jdbc:postgresql://localhost:5434/classifier` |

Таблицы маршрутов создаются при старте приложения. Если подключение отклонено, проверьте, что Docker Desktop работает и `docker compose ps postgres` показывает запущенную базу.

## Локальная разработка и тесты

Для локального запуска на Windows нужны JDK 17 и PostgreSQL. Удобно поднять только базу в Docker, а приложение запустить через Gradle Wrapper.

```powershell
docker compose up -d postgres
$env:CLASSIFIER_DEMO_ENABLED = 'true'
.\gradlew.bat bootRun
```

При таком запуске [веб-интерфейс](http://localhost:8082/) и [Swagger UI](http://localhost:8082/swagger-ui.html) доступны на порту 8082. Переменная `CLASSIFIER_DEMO_ENABLED` включает загрузку учебных примеров. Для остановки приложения нажмите `Ctrl+C`.

Для запуска тестов на Windows выполните команду ниже.

```powershell
.\gradlew.bat test
```

Интеграционные тесты используют Docker через Testcontainers. На Linux и macOS команды Gradle выполняются через `./gradlew`.
