# Спецификации изделий — задание 2-1

Модуль реализует практическую работу «Приёмы моделирования спецификации изделий (Bill of Materials)» на данных интернет-магазина электроники.

## Модель

Общий справочник хранит группы, модели и изделия в одном дереве с явным node_kind. В BOM регистрируется ссылка на модель или изделие, а не дубликат его кода и названия. Поэтому старые параметры и поиск доступны для того же изделия.

Дерево классификации и граф состава решают разные задачи. Родитель изделия в классификаторе — класс; входящий компонент задаётся строкой спецификации. Один ресурс может встречаться в нескольких позициях и нескольких сборках. Компонент может принадлежать любому классу. Типы по отношению к производству: сборочная единица, деталь, материал, покупное изделие. Тип не запрещает собственную спецификацию: например, деталь может расходовать материал.

Сохраняются PostgreSQL 15, Spring Boot, Kotlin для DTO/сервисов, Java для REST-контроллера и существующий интерфейс на ES-модулях. Firebird в методичке указан как рекомендуемый инструмент; переписывание действующей системы для него не требуется. Репозиторий BOM использует JDBC, чтобы SQL-функции расчёта были едиными для приложения и SQL-клиента.

## Соответствие требованиям

## Версии и наследование

Черновик можно редактировать или удалить. При утверждении состав фиксируется. Изменение оформляется новым черновиком с `baseId`, указывающим на утверждённую версию. То же изделие означает новую редакцию; другое изделие — модификацию. Номер редакции назначается автоматически в пределах изделия. Описание изменения обязательно.

Базовые строки не копируются. Эффективный состав строится по всей цепочке баз: ближайшее определение номера позиции имеет приоритет. Локальное исключение скрывает позицию, включая унаследованную. Отмена локального изменения удаляет переопределение и восстанавливает базовую строку; если базовой строки не было, позиция исчезает. Номер позиции — идентификатор в составе; перенумерация выполняется исключением старой и созданием новой позиции.

Строка может ссылаться на конкретную утверждённую спецификацию компонента. Она должна принадлежать этому же компоненту. Без ссылки компонент считается ресурсом без дальнейшего раскрытия, даже если у него существуют другие версии. Это позволяет явно выбирать покупное или собственное исполнение и не менять прошлый расчёт при создании новой версии компонента.

Единица нормы фиксируется при регистрации изделия в `classifier_node.unit_of_measure_id`; это единица всех его вхождений. Разные единицы в одной позиции и автоматические пересчёты единиц не поддерживаются. Названия/коды и принадлежность классу читаются из текущего справочника; неизменяемость истории относится к составу и количествам, а не к снимку справочника.

## Расчёт и целостность

Для количества `Q` исходных изделий расход по пути равен `Q × q1 × q2 × … × qN`. Повторные вхождения не удаляются: при двух ветвях к одному ресурсу учитываются обе. Итоги группируются по ID ресурса, а не только по классу или единице. В результаты включаются все компоненты выбранного класса, включая промежуточные сборки, если они входят в этот класс. Само исходное изделие не считается своим компонентом.

Проверяются прямые и косвенные циклы по изделиям, в том числе через старую версию того же изделия. При обнаружении цикла изменение откатывается. SQL-обход дополнительно помечает цикл и прекращает рекурсию по этой ветви; сервис не возвращает частичный расчёт. Нет искусственного ограничения глубины, но большие графы требуют соразмерных ресурсов сервера.

Внешние ключи защищают используемые изделия, единицы и базовые версии от удаления. SQL-триггеры запрещают изменение утверждённых версий и их строк, неутверждённые базы и несовместимые ссылки на версии компонентов. При утверждении проверяются пустой состав и циклы. Все изменения BOM через сервис сериализованы транзакционной advisory-блокировкой: назначение редакций и проверка состава не конфликтуют с параллельными изменениями модуля. Рекомендуемый путь редактирования — REST API; прямые SQL-скрипты должны выполнять согласованный набор изменений в одной транзакции.

`BomInitializer` загружает дополнение после JPA и прежних SQL-скриптов. Таблицы создаются при отсутствии, функции и триггеры обновляются без удаления данных. Это аддитивное расширение; для будущих несовместимых изменений потребуется полноценная миграция схемы.

## Интерфейс и API

Раздел **Составы изделий**: `http://localhost:8082/#/bom`. Создайте изделие в классификаторе и зарегистрируйте его в разделе спецификаций. Затем создайте черновик, добавьте позиции, проверьте раскрытие/расход и утвердите версию. Для изменения нажмите «Создать новую версию / модификацию» и выберите изделие и базу.

Базовый путь API: `/api/v1/bom`.

| Метод и путь | Назначение |
|---|---|
| `GET /products`, `POST /products` | Изделия; регистрация `{nodeId, kind, unitId}` |
| `GET /specifications`, `GET /specifications/{id}` | История версий и карточка |
| `POST /specifications` | Черновик `{productId, baseId?, description}` |
| `DELETE /specifications/{id}` | Удаление черновика |
| `POST /specifications/{id}/release` | Утверждение |
| `GET /specifications/{id}/lines` | Эффективный состав с указанием источника |
| `PUT /specifications/{id}/lines/{position}` | Добавление/замена `{componentId, componentSpecificationId?, quantity}` |
| `DELETE /specifications/{id}/lines/{position}` | Исключение позиции |
| `GET /specifications/{id}/local-positions` | Номера локальных изменений, включая исключения |
| `DELETE /specifications/{id}/overrides/{position}` | Отмена локального изменения |
| `GET /specifications/{id}/explosion?quantity=3` | Полное раскрытие |
| `GET /specifications/{id}/totals?quantity=3&classId=…` | Итоги по классу ресурсов |

Ошибки: 404 — отсутствующая ссылка; 400 — цикл; 409 — редактирование утверждённой версии или конфликт ограничений БД; 422 — неверная норма, номер позиции, пустой состав, неутверждённая/чужая версия компонента. Норма допускает 13 целых и 6 дробных знаков; количество исходных изделий положительное с теми же пределами. Промежуточные SQL-вычисления используют `numeric` без округления до масштаба строки.

Группы доступны при фильтрации расчёта.

### Запуск и переход с прежних данных

Выполните `docker compose up -d --build` из корня проекта и откройте [Составы изделий](http://localhost:8080/#/bom). Compose задаёт `CLASSIFIER_DEMO_ENABLED=true`. Для локального запуска с Java 17 поднимите PostgreSQL командой `docker compose up -d postgres`, задайте эту переменную окружения и выполните `./gradlew bootRun` или `gradlew.bat bootRun` в Windows. Откройте [порт 8082](http://localhost:8082/#/bom). По умолчанию локальная конфигурация подключается к базе Compose на порту 5434.

Схема BOM устанавливается до загрузки данных. `bom-demo.sql` создаёт ветвь «Комплекты электроники» и сохраняет отметку `bom-electronics-demo-v1` в той же транзакции под блокировкой BOM. После успешной загрузки отметка защищает пользовательские правки и удаления при повторном запуске. Для ручной загрузки в уже инициализированную БД используйте `psql … -v ON_ERROR_STOP=1 -f docs/bom/demo.sql`. Для чистой установки без примеров установите `CLASSIFIER_DEMO_ENABLED=false` до запуска.

В каталоге откройте «Электроника → Спецификации». На вкладке «Обзор» показаны все версии составов, включая черновики и составы товаров из других групп. Ссылка открывает нужную версию в BOM. Компоненты распределены по товарным категориям. Ryzen 5 находится в «Комплектующие для ПК → Процессоры», а зарядное устройство — в «Аксессуары → Зарядные устройства».

При обновлении сохраните том `pgdata`. Скрипт `catalog-bom-layout.sql` переносит уже загруженные товары по их кодам, сохраняя ID и составы. Пустые служебные группы и исходный неизменённый стенд с заготовками удаляются. Ранее загруженные производственные спецификации и пользовательские составы доступны через «Все составы и версии». Если Galaxy S24 недоступен, загрузчик использует подходящий Galaxy S24 Ultra. Если обе записи удалены или несовместимы по типу или единице, загружаются четыре семейства, а смартфон и его комплект пропускаются.

### Проверка через интерфейс

1. В блоке «Примеры комплектов электроники» откройте базовую и улучшенную комплектации каждого семейства. Сверьте прямой состав с таблицей. У обеих карточек указан статус «Утверждён» и версия 1. В карточке модификации есть ссылка на базу и блок «Изменения этой версии».
2. Введите количество из таблицы, оставьте «Все компоненты» и нажмите «Рассчитать потребность». Для Gaming PC откройте ссылку из строки «Комплект охлаждения» и раскройте в результате расчёта все уровни. Вентиляторы и контроллер видны по путям `7 → 1` и `7 → 2`. Для видеонаблюдения проверьте единицу «м», для комплекта со смартфоном — присутствие Galaxy в полном расчёте.
3. Найдите Gaming Set Standard версии 2 в блоке «Все составы и версии» с фильтром «Черновики». В нём исключён коврик и добавлен контроллер. Нажмите «Вернуть как было» для коврика, «Изменить» для замены мыши и «Добавить компонент» для новой позиции. Сравните результат с утверждённой версией 1.
4. Чтобы проверить утверждение и историю, создайте собственный черновик кнопкой «Создать новую версию / модификацию». Выберите то же изделие для новой редакции или другое для модификации. После утверждения запись остаётся в истории, а редактирование доступно через следующий черновик.

### Автоматические проверки

```bash
./gradlew build
./gradlew test --tests 'com.classifier.controller.BomControllerTest'
psql … -v ON_ERROR_STOP=1 -f docs/bom/demo-check.sql
BOM_TEST_URL=http://127.0.0.1:18083 node docs/bom/ui-smoke.cjs
```

Gradle-тесты используют PostgreSQL Testcontainers и требуют работающего Docker Engine. SQL-проверка запускается на отдельной БД с чистыми демоданными и откатывает свои изменения. Она сверяет эффективные составы всех пяти пар, локальные позиции, единицы, расчёт, исключение и повторную загрузку. Браузерная проверка использует Playwright и отдельный экземпляр приложения с демоданными.

Интеграционные сценарии также проверяют циклы по изделиям, фиксацию версии вложенного состава, дробные количества, расчёт по подклассам, замену и восстановление строк, защиту утверждённой истории и совместимость с существующими спецификациями.
