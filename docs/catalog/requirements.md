# Проверка требований к параметрам изделий

Все восемь пунктов реализованы. Формулировки соответствуют заданию ПР №3, раздел 1.1.

| Требование | Как работает и где проверить |
|---|---|
| Ведение числовых параметров и перечислений | Разделы «Числовые параметры» и «Перечисления»: определения, единицы, списки вариантов, добавление и редактирование. |
| Наследование параметров | Назначение группе действует у её потомков. В карточке показан источник. Наследуется определение параметра, значения каждого изделия вводятся отдельно. |
| Редактирование состава параметров подкласса | В карточке можно назначить собственный параметр, исключить унаследованный или вернуть его повторным назначением. Это действует и для чисел, и для перечислений, включая потомков подкласса. Соседние ветки не меняются. |
| Ограничения числовых значений | У определения параметра задаются минимум и максимум. Любая граница может отсутствовать. Очистка поля в редакторе снимает границу. Значения и изменения границ проверяются в сервисе и БД. |
| Редактирование значений | Вкладка «Числовые»: указать, изменить, очистить число. «Варианты и свойства» конкретного изделия: выбрать или снять один вариант списка. У модели отдельно настраиваются допустимые варианты выпуска. |
| Поиск класса с параметрами и атрибутами | «Поиск и анализ изделий»: выбрать раздел и выполнить поиск без условий либо задать условия. Карточки результатов показывают числовые значения и выбранные варианты. Есть поиск по названию и коду. |
| Отбор по значениям | Числовые диапазоны и выбранные варианты можно сочетать. Все заданные условия действуют одновременно. Дополнительная галочка включает модели, которые допускают выбранный вариант. Список условий включает определения из подклассов, даже если у общей группы их нет. |
| Агрегаты параметров | Карточка раздела → «Анализ»: количество заполненных значений, минимум, максимум, среднее, сумма; для перечислений — распределение по выбранным вариантам. Результаты вычисляются по актуальным данным, отдельные таблицы итогов не создаются. |

## Наглядный пример

Для проверки на отдельной инициализированной БД один раз загрузите `src/main/resources/catalog-parameters-demo.sql` через `psql -v ON_ERROR_STOP=1 -f`. Скрипт создаёт раздел **«Учебный пример: параметры и наследование»**.

- **Заготовки** наследуют длину и вид обработки поверхности. У матовой заготовки длина 0,5 м; у полированной — 1,2 м. Допустимая длина от 0,01 до 10 м.
- **Покупные наборы** явно исключают длину и обработку, добавляют собственный параметр «Число предметов в наборе». У учебного набора 6 предметов.
- В анализе общего раздела доступны оба числовых параметра, хотя число предметов назначено лишь подклассу наборов. Для длины результат: количество 2, минимум 0,5, максимум 1,2, среднее 0,85, сумма 1,7 м. Распределение обработки: по одному изделию каждого вида.

В карточке наборов исключённые параметры перечислены под списком. Для возврата используйте «Назначить параметр» или «Назначить характеристику». Для повторного исключения — кнопку «Исключить» в строке.

## Правила изменения состава

В существующих таблицах `node_numeric_parameter` и `node_enumeration` добавлен флаг `excluded`. Ближайшее к изделию назначение определяет, действует ли параметр. Потомок может явным назначением вернуть параметр, исключённый предком. Для перечислений действующие ограничения вариантов выше по дереву продолжают проверяться.

«Снять назначение / ограничение» удаляет только собственную настройку: после этого снова работает наследование. «Исключить» явно выключает параметр для выбранной ветки. Если исключение сделает сохранённые значения недопустимыми, вся операция отклоняется. Сначала нужно очистить или перенести эти значения; автоматически они не удаляются.

Минимум и максимум относятся к общему определению числового параметра. Для PATCH API сохранена семантика пропущенных полей: флаги `clearMinValue` и `clearMaxValue` явно снимают соответствующую границу.

## Область расчётов

Поиск, отдельные фильтры и агрегаты учитывают выбранную запись и всех её потомков типов MODEL и PRODUCT. Группы не считаются изделиями. Пустые значения не входят в агрегаты. Если значения заполнены и у модели, и у её исполнений, это отдельные записи, что указано в интерфейсе. Количество записей и сумма характеристик не являются складскими остатками или расходом материалов по спецификации.

Основные API: `/api/v1/nodes/{id}/parameter-options`, `/numeric/parameters/effective`, `/numeric/parameters/{parameterId}/exclusion`, `/enumeration-bindings/{enumerationId}`, `/numeric/aggregates/{parameterId}`; последние четыре пути указаны относительно `/api/v1/nodes/{id}`.

- Полный набор: 190 тестов, без ошибок и пропусков. Включены сценарии исключения и возврата параметров, защиты сохранённых фактов, снятия числовых границ, выбора параметров подклассов и расчётов.
- На отдельной копии рабочей БД сохранены все прежние строки во всех 24 таблицах. Миграция добавляет поля и учебные данные; существующие записи не удаляются.
- В Chromium пройдены фильтр по длине, сводка и распределение, исключение/возврат обоих типов параметров, снятие границ через форму и поиск в пустом классе. Ошибок JavaScript нет. Скрипт: `parameters-ui-smoke.cjs`, только для отдельного тестового экземпляра.
