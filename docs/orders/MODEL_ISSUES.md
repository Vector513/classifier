# Уточнения моделей ЛР7

Реализация следует сохранённой пользователем ER-диаграмме `models/er.png`, диаграмме классов `models/classes.svg` и прецедентам `models/use-cases.png`. Состав новых таблиц и названия полей соответствуют ER; варианты имеют самостоятельный ID и не требуют создания узла классификатора.

Выявлены пробелы, которые без дополнительных ограничений допускают некорректные данные:

1. Две ссылки позиции заказа (`product_id`, `variant_id`) требуют XOR: заполнена ровно одна. GROUP, MODEL и изделие с профилем шаблона нельзя включать как готовое изделие. Количество и номер позиции положительны.
2. `value JSONB` и `enumeration_value_id` требуют альтернативного хранения: для ENUM задана только ссылка на допустимое значение, для прочих типов — только JSONB-скаляр соответствующего типа. Необходимы проверка обязательности, границ и принадлежности параметра шаблону варианта.
3. Для `expression` нужны фиксированные виды узлов, допустимые поля каждого вида, порядок аргументов, ограничения арности и типов, запрет циклов дерева и вызовов функций. Одного FK на родителя для этого недостаточно.
4. Корень может принадлежать либо правилу, либо функции. Нельзя одновременно использовать его как дочернее выражение или как корень другого владельца. Ссылки на параметры изделия и формальные аргументы проверяются в своём контексте.
5. Дополнительно нужны уникальные коды правил внутри шаблона и коды формальных параметров внутри функции; диаграмма явно показывает не все эти UQ.
6. Модель не хранит версии шаблонов и правил. Изменение, которое сделало бы существующий вариант некорректным, отклоняется. Вариант, включённый в заказ, нельзя незаметно изменить: для другого исполнения создаётся новый вариант и заменяется позиция.
7. У выражений и формальных аргументов нет метаданных размерности и преобразования единиц. Числа интерпретируются в единицах, заданных параметром; автоматическое преобразование, например метров в миллиметры внутри формулы, не предполагается.

Эти уточнения не требуют изменения диаграмм или добавления сущностей. Они реализуются ограничениями БД и SQL-функциями. Публичные данные мастер-справочника, код и имя шаблона остаются разными атрибутами, как на ER: один шаблон на выбранную запись справочника.

Проверки реквизитов: у заказчика указан хотя бы телефон или электронная почта; желаемый срок заказа не предшествует дате оформления. Эти правила заданы CHECK-ограничениями. Код параметра, правила, функции и формального аргумента — идентификатор из латинских букв, цифр и подчёркивания (первый символ — буква или подчёркивание); отображаемые названия допускают русский текст.
